# R2f：終端報酬による過大な可塑性更新を分離した研究用報酬設計

更新日：2026-10-19（JST） / 状態：**実装済み研究候補、戦闘能力は未検証、production 不採用**

## 1. 目的と観測事実

- [実際のR2e訓練 run 39205782160](https://github.com/Unjuno/connectome-fighter/actions/runs/39205782160) は MaleCNS/Shiu で GARNET（Gen49）対 NEZ。3600フレーム、60判断、与ダメージ30 HP・被ダメージ40 HP・敗北。更新提案は固定ZEN/LUD/NEZの全条件でUtilityが低下し、Gen50へ**進めなかった**。
- 同じ訓練履歴の報酬成分は、ダメージ -0.025、距離ポテンシャル +0.015625、終端 -2.0、合計 **-2.009375**。
- 全更新量のうち終端判断時の平均倍率減少が約 **94.77%** だった。ただし最後の判断には他の成分も含まれ、重み更新は指数・クリップを含むため「94.77%が終端報酬の因果寄与」とは断定しない。
- [別実験の baseline run 39201908982](https://github.com/Unjuno/connectome-fighter/actions/runs/39201908982) は48試合中47試合が無ダメージ引き分け。**600フレーム短時間ベースライン**であり、3600フレームのGen49訓練勝率ではない。
- [PR #86](https://github.com/Unjuno/connectome-fighter/pull/86) の無ダメージペナルティ除去だけでは、固定比較で勝利から引き分けへの後退を生じ不採用。[PR #87](https://github.com/Unjuno/connectome-fighter/pull/87) の終端 credit **0.1倍**も独立6条件の選択ゲートで不採用。報酬を小さくすれば必ず強くなるという主張は否定されている。

## 2. 設計差分

**勝率・ダメージを測る外的評価関数はR2eのまま維持する。学習用シナプス変調信号だけを別ID `R2f-credit-balanced-v1` として区別する。**

| 成分 | 既存R2e 学習 | R2f 学習候補 | R2fの外的評価 |
|---|---:|---:|---|
| 勝ち / 負け | +2 / -2 | **+1 / -1** | R2e基準のまま |
| 無ダメージ引き分け | -0.25 | **0** | R2e基準のまま |
| ダメージ交換ありの引き分け | -0.05 | **0** | R2e基準のまま |
| 早期勝利KOボーナス最大 | +0.25 | **+0.125** | R2e基準のまま |
| 与・被ダメージ差 | HP差 / 400 HP | **変更なし** | 変更なし |
| 距離ポテンシャル | 0.05、180/960 game px | **変更なし** | 現行どおり評価から除外 |
| 60フレーム判断 / 神経20 ms窓 | 現行 | **変更なし** | 変更なし |
| KC-MBON 学習率、減衰、境界 | 0.01 / 0.9 / [0.8,1] | **変更なし** | 変更なし |

- 勝敗を学習時に半分にしても勝敗の順序は維持されるが、プラスチック回路の学習性能は保証されない。
- 無ダメージ引き分けの終端負信号を止めると、何も学習しなかった対戦で「接近関連シナプスを根拠なく抑制する」効果を避けられる。接近に伴う実際の距離ポテンシャル信号はそのまま残す。
- 攻撃ボタン・前進ボタン・行動多様性への直接加点はしない。無関係なキー連打を学習目標にしないため。
- 固定R2eコード、R2e評価、承認済み推論、LIVE、既存の `combat-candidate-training`、シード、チェックポイントを変更していない。
- 勝敗/無ダメージの**2要因を同時に変更した候補**なので、この候補単独の比較から各要因の因果寄与は識別できない。次の実対戦では2×2要因実験で独立に比較する。

## 3. 数式と変数表

学習判断の信号：

\[
s_t=d_t+p_t+g_T T_t^{\mathrm{WL}}+g_K K_t+D_t.
\]

評価ではなく「既存のeligibilityを使うKC-MBON更新器への入力」である。ここで引き分けなら勝敗項は0、最終判断以外は終端項すべて0とする。R2fは \(g_T=g_K=0.5\)、引き分け \(D_t=0\)。対照R2eは \(g_T=g_K=1\)、無ダメージ引き分け \(D_t=-0.25\)、他の引き分け \(D_t=-0.05\)。

| 記号 | 意味（日本語） | SI単位 | 定義 | 定義域・前提 | 型 |
|---|---|---|---|---|---|
| \(s_t\) | 判断tの可塑性変調信号 | 1 | 上記の和 | 有限値、完了試合のみ | 実スカラー |
| \(d_t\) | 与・被ダメージ差の信号 | 1 | \((\Delta HP_{\mathrm{dealt}}-\Delta HP_{\mathrm{taken}})/400\) | HPはゲーム単位。各差は0以上 | 実スカラー |
| \(p_t\) | 距離ポテンシャル差の信号 | 1 | \(0.05(\Phi_{t+1}-\Phi_t)\) | 完了終端で \(\Phi=0\) | 実スカラー |
| \(\Phi_t\) | 距離状態の無次元ポテンシャル | 1 | \(-\min(\max(x_t-180,0),960)/960\) | xは相対横距離（ゲームpixel） | 実スカラー |
| \(x_t\) | 両者の横方向距離 | 非SIゲームpx | \(\lvert x_{P1,t}-x_{P2,t}\rvert\) | 0以上 | 実スカラー |
| \(T_t^{\mathrm{WL}}\) | 勝敗終端信号 | 1 | 最終のみ勝ち+2、負け−2、引き分け0 | R2e基準から取得 | 実スカラー |
| \(K_t\) | 早期KO加点の元値 | 1 | 最終勝利KOのみ0～0.25 | 敗北にはなし | 実スカラー |
| \(D_t\) | 引き分け終端加点 | 1 | R2fでは常に0 | 引き分け最終判断のみ | 実スカラー |
| \(g_T,g_K\) | 終端勝敗・KOの倍率 | 1 | R2fでは両方0.5 | (0,1]、現版で固定 | 実スカラー |
| \(t\) | 判断番号 | 1 | 0始まり整数 | 完了判断列 | 整数スカラー |
| \(\Delta HP\) | 判断区間内のHP減少量 | 非SIゲームHP | 区間の開始HP−終了HP | 0以上、回復なし | 実スカラー |

**次元チェック：** HP/HP、px/pxはいずれも無次元、\(g_TT_t\)、\(g_KK_t\)、\(D_t\)も無次元。したがって\(s_t\)のSI単位は1で整合する。ゲームpxをメートル、HPをジュールとして扱わない。

**実観測の1ラウンドに対する静的算術例：** R2eの \(-2.009375\) は、他成分固定のまま勝敗のみ半分にすると \(-1.009375\)。これは**元の対戦ログの再採点**であり、重み再計算・新しい試合・勝率改善は意味しない。前回PR #87で不採用になった0.1倍を再利用してはいない。

## 4. 実装範囲と使い方

- `src/connectome_fighter/combat_reward_r2f.py`：canonical R2e入力検査を再利用し、報酬成分の算術一貫性を確認した上で新しい学習用signalを返す。R2e評価関数を別経路で保持する。
- `configs/reward_r2f_credit_balanced_v1.json` / `configs/plasticity_r2f_credit_balanced_v1.json`：固定された候補IDとパラメータ。変更すると検証が失敗する（別IDが必要）。
- `scripts/update_malecns_valence_plasticity.py`：R2fを明示指定した場合のみ上記新実装へ配送。R2e既存分岐は不変。実コネクトーム用スパイク・候補エッジ検査も既存経路のまま。
- `src/connectome_fighter/combat_reward_r2f_checkpoint.py` と `scripts/fork_r2f_candidate.py`：古いR2e stateのSHAを検証して新たな研究用パスに複製し、全係数と世代・重みを保持。研究用のforkを生成しただけでは学習・評価・昇格は起きない。
- `tests/test_reward_r2f_credit_balanced.py`：終端・引き分け・KO・非訓練記録排除・成分不正・変更されたキー・旧R2e不変・fork SHAをテスト。
- `.github/workflows/reward-r2f-research-contract.yml`：CPU上のソフトウェア契約検証のみ。本物の試合実行、Brian2パフォーマンス計測、学習改善判定ではない。

研究用 fork の実行例：

```bash
python scripts/fork_r2f_candidate.py \
  --source-state /verified/r2e/state/GARNET.npz \
  --research-state runs/r2f/parent/GARNET.npz
```

ユーザー入力の正しい旧チェックポイント、候補シナプスParquet、正しいbody-IDスパイクおよび実ゲームの完了traceを用意したときだけ、既存 updater を `--reward-config configs/reward_r2f_credit_balanced_v1.json --plasticity-config configs/plasticity_r2f_credit_balanced_v1.json` で研究用forkへ適用すること。元のGen49を直接指定してはならない。現時点でR2f研究用の実試合は未実行である。

**実装・再現前提：** FightingICE v7.1、pyftg 2.3、Java 21、MaleCNS v1.0、pinned Shiu LIF / Brian2 2.5.1 / NumPy 1.24.0 / Cython 0.29.36 / Python3.10のコンパイル済みキャッシュとPython3.11のゲームbridge。ソフトウェアテスト側はGitHub Actions ubuntu-24.04、Python3.11、NumPy1.26.4、pandas2.2.3、pytest8.3.5。Cythonのキャッシュは実行パス・Python ABIが不一致なら再利用できない。実測ベンチマーク時間や継続稼働保証はここでは主張しない。

## 5. H / T / D / C / U

**H（反証可能仮説）：** Gen49から同一試合条件でR2fが生成した候補はR2eより、未使用シードでの平均R2e評価Utilityを少なくとも+0.05（無次元）改善し、勝敗クラスの後退を増加させず、接触・ダメージ発生率が低下しない。これは事前に決めた実務上の探索閾値であり統計的に証明された最小重要差ではない。

**T（最小検証）：** 4条件の要因比較——(1)R2e元仕様、(2)終端だけ0.5倍、(3)引き分けの学習終端を0、(4)両方=R2f。各条件について同一Gen49ソース、3以上の**独立した訓練seed**、同一訓練相手ローテーション。固定ZEN/LUD/NEZに各2個以上の**新しい**評価seedを割り当てる（探索段階の最小数：計12訓練試合+72評価試合）。選択結果を見てから評価seedを入れ替えない。探索後の確証実験は少なくとも各条件10独立訓練seedと別の凍結評価集合で実施。勝敗、HP差、初撃までの時間、無ダメージ率、行動頻度・エントロピー、倍率境界への張り付きを記録。途中で有効な結果が得られず予算が尽きればUNCERTAINとして停止。

**D（合否）：** 契約テストPASSは算術とガードのみ。候補選択PASSには同seedで平均Utility+0.05以上、対応ケースの3分の2以上で改善、勝ち→引き分け/負け等の結果後退0件、接触率非減少が必要。確証的PASSには、**独立訓練seedをクラスタ単位とする**事前登録95%信頼区間の下限が+0.05を超えること。満たさない場合はFAIL（悪化が明確）またはUNCERTAIN（精度不足）。同一方策で多数試合しただけでは独立訓練seedと数えない。

**C（破れ方）：** 終端信号低減が有益な勝利更新まで弱める、R2fの2要因が相殺する、固定seedへの過適合、符号依存・減衰のみ可塑性の不可逆性、行動60フレームの遅延、入出力ルーティング不適合、相手の攻撃能力差。報酬係数変更のみで無接触を解決できるとは限らない。

**U（不確かさ）：** ゲーム/Poisson RNG、訓練seedクラスタ分散、対戦相手分布、実神経データ注釈、KC-MBON候補符号・分区、float32保存/float64更新、Cython/NumPy/Python ABI、飽和クリップ、Actions実行環境差。今回の単一既存試合から戦闘性能改善の合成標準不確かさ \(u_c\) は推定不能、包含係数 \(k\) は未設定。実験開始前に原データ・runtime SHA・コードSHA・seed・CPU仕様を固定する。

## 6. 分野横断・出典

- **計算神経科学：** KC-MBONと神経spike活動の因果経路の同定はゲーム報酬の実装とは別問題。Shiu et al., *Nature* (2024), DOI: [10.1038/s41586-024-07763-9](https://doi.org/10.1038/s41586-024-07763-9)、Aso et al., *eLife* (2014), DOI: [10.7554/eLife.04580](https://doi.org/10.7554/eLife.04580)。
- **強化学習・制御：** 行動を直接報酬化せず、外的目標を保持。原理的なpotential-based shapingと本研究の部分観測・符号依存シナプス更新での方策不変性は同一視しない。Ng, Harada & Russell (1999), *Policy invariance under reward transformations*。
- **統計的実験設計：** 同seed対応比較・独立訓練反復・確証用holdoutを分離して過適合を評価する。
- **ソフトウェア再現性：** 状態SHA、入力runtime/graph ID、Python ABI、検証ゲートを固定する。

**ERROR CHECK：** R2eの評価関数・学習ワークフロー・既存リリースは不変。新設定を指定したときのみR2f配送。数値例は -0.025 + 0.015625 - 1 = **-1.009375**。科学的な性能改善は未検証。ソフトウェアCIが成功しても実ゲームでの上達を意味しない。
