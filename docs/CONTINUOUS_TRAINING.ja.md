# Continuous Learning League and Spectator Design (historical)

This compatibility path is now English-only. This document describes the **legacy PPO-readout design**, not the canonical MaleCNS training lane. For the current candidate schedule and reward, see [COLOSSEUM.md](COLOSSEUM.md).

## Goal

The intended deliverable is not a one-shot experiment: each FightingICE 7.1 character (`GARNET / ZEN / LUD / NEZ`) owns an independent fly-connectome-derived controller lineage, resumes checkpoints in the cloud, and exposes fights and neural activity to a web spectator.

## One brain per character

The four characters may reference the same verified Drosophila topology and routing contract. Checkpoint lineage/ID, actor readout, value-head parameters, optimizer state, recurrent state, action-sampling RNG seeds, generation counters, and training-match counters remain independent.

In the fixed-connectome legacy condition, immutable sparse graph tensors may be shared inside a process to reduce memory use; trainable and recurrent state must not be shared. Plastic internal edge weights must also remain character-specific.

## Execution model

A hosted Actions job is not a persistent process. The historical proposal divided training into bounded chunks:

```text
restore four character checkpoints
  -> two training fights (each character participates once)
  -> PPO readout update
  -> four new checkpoints
  -> one frozen evaluation fight
  -> replay, neural telemetry, and metrics
  -> Pages deployment
  -> next scheduled run restores the checkpoints
```

Three chunks cover all six character pairings, with fixed work per chunk.

### Training invariants

Only one job writes checkpoints at a time. Policies remain frozen during matches; updates follow collection. Incomplete or disconnected rounds are excluded, not scored as losses. Evaluation never updates weights. The historical terminal reward is win +1, loss -1, draw 0.

Checkpoints include model/readout, optimizer, RNG, generation, match count, source commit, connectome hash, routing hash, and schema. Actions cache is not the sole checkpoint store: it is for immutable graph/runtime dependencies. Historical learned state uses the `training-state` release.

## Historical initial learning scope

Topology, internal edge weights, and sensory routing were fixed. Character-specific action readouts and value heads were trainable under `PPO-readout-v1`. Success in that design would not mean that all internal connectome synapses learned through reinforcement. The initial goal was persistent learning and observation while retaining a large biological graph in the control path.

This legacy artificial-readout path is **not canonical MaleCNS/Shiu evidence**.

## Pages spectator

Pages renders static JSON generated by Actions; it does not compute fights. Character cards show generation, training matches, operational league Elo, and checkpoint ID.

Historical `latest-replay.json` records both characters/checkpoint IDs, frame, HP, energy, x/y, selected action, and result. The legacy viewer reconstructs a simple two-dimensional telemetry replay rather than running Java in the browser; it is not official ScreenData.

Historical neural displays show activation mean/max, fraction above 0.75, real FlyWire node IDs with the largest increase, and highly active descending/readout IDs. These values are dimensionless engineering-model states, not measured firing rates. Anatomical labels absent from annotations must not be invented.

## From CI to continuous compute

The historical proposal used hourly chunks with a single-writer lock. A future self-hosted runner could provide continuous compute while Actions orchestrates and Pages displays results. This historical proposal does not configure the current scheduler.

## Research separation

Persistent learning agents are an engineering result. An advantage of biological topology over matched rewiring is a separate A/B claim. Success at the former does not establish the latter.
